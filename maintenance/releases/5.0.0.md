# Publicación 5.0.0

Fecha: 3 de noviembre de 2026. Baseline: v4.7.2; HEAD previo 753d535. Publicación y actualización del sitio local de documentación autorizadas expresamente por el usuario.

## Compatibilidad

Los contadores de autenticación/correo, autorizaciones de descarga y payloads Async persisten en SQL, sin drivers de archivos. Las sesiones usan SQL o Redis; native se rechaza y los sitios sin base de datos usan disabled. Nuevos módulos rate-limits y runtime-storage, con migraciones MySQL/SQLite. Las imágenes y documentos pertenecen a Media. Los usos actuales de localStorage se conservan, incluida la recuperación local del editor junto al autoguardado SQL existente.

Antes de actualizar una aplicación, detener disparadores y dejar terminar workers. Aplicar las migraciones a las conexiones seleccionadas; los archivos antiguos de contadores/autorizaciones y tareas no se importan automáticamente. Las sesiones nativas anteriores requieren nuevo acceso. Consultar docs/persistencia.md.

## Verificación

- PHP completo: 633 pruebas, 6222 aserciones, sin fallos ni errores; 8 omitidas. PHP 8.3.35, SQLite y MariaDB 10.4.24 en esquemas temporales.
- Lint: 539 archivos PHP válidos. Skills: 14 válidas, 80 enlaces locales.
- JavaScript: 101 pruebas, 82 correctas y 19 omitidas; cero fallos. Los recorridos de navegador no están certificados por esta ejecución.
- Composer validate --strict y auditoría del lock correctos, sin avisos de vulnerabilidades.
- PHPStan nivel 5: sin errores. La eliminación de una condición redundante tras retirar native se verificó además con 23 pruebas de sesiones/CSRF/almacenamiento (90 aserciones, una omitida).
- Las comprobaciones del sitio documental se registran al completarse.

## Distribución

Etiqueta anotada prevista v5.0.0, sin añadir version a composer.json. Se conserva el Composer lock del framework; la instalación de PHPStan para comprobar la publicación utiliza su versión ya fijada.

El sitio gframe-docs debe consumir ^5.0, fijar v5.0.0 en su lock y usar SQLite para sesiones y límite del formulario de contacto. La documentación pública debe leerse desde el paquete instalado al validar producción; se conservan las personalizaciones del sitio mediante el actualizador.
