# Verificación — Autoguardado privado

Implementación 2026-10-15. Se conserva el trabajo anterior. Fuentes: clases GFrame/Content, módulo content-autosave y configuración/cliente del rich-text-editor; no hay endpoint genérico publicado ni cambios a sitios instalados.

- T1: `php packages/phpunit/phpunit/phpunit tests/ContentAutosaveTest.php`: 3/3, 40 aserciones. SQLite real y dos procesos sincronizados para creación y actualización: un ganador y un conflicto en cada ronda. Scope, HTML saneado, base pública antigua, descarte viejo, expiración y tombstone comprobados. El artículo público permanece intacto.
- T2/T3: `node --test tests/js/content-autosave.browser.test.cjs` con Chrome/PHP CLI/SQLite reales y transporte interceptado: 1/1, 73,853 s. Recuperación/undo, tokens, intervalo, una petición activa, escritura durante petición, fallo 503/reintento, dos pestañas, conflicto sin pérdida, publicación con autosave en vuelo y cambios posteriores, descarte confirmado/cancelado, lectura y teardown.
- T4: suite PHP completa: 504 pruebas, 4906 aserciones, 12 omitidas por entorno; exit 0, 6:04,354. El test MySQL añadido después del descubrimiento de esa suite se ejecutó aparte: omitido por falta de GFRAME_TEST_MYSQL_DSN. Su clase ya forma parte del job MySQL de CI; no se afirma ejecución local de MySQL.
- Suite JS sin navegador: 94 pruebas, 80 pasan, 14 omisiones explícitas de navegador; exit 0. Regresión Chrome posterior: media-field-controls, media-toast, media-writing, rich-text-protection y rich-text-scroll: 5/5 sin omisiones, 75,025 s.
- PHP enfocadas de módulos/documentación: 34/34, 464 aserciones. Tras el ajuste final de guías: 9 pruebas, 170 aserciones, una omisión MySQL. Skills: 14/79 enlaces. Lint PHP de release: 451 archivos válidos; composer validate y diff --check pasan.

Sensibilidad: prueba de procesos fuerza que dos escritores usen la misma versión; el affected real decide el ganador, sin confiar en el SELECT de matched del ORM. Un fallo en navegador detectó uso del serializer DOM con nodo AST; se corrigió al serializer HTML nativo. El conflicto entre pestañas inicialmente se comprobaba antes de terminar el segundo autosave: se sustituyó la espera de un mensaje previo por la comprobación de la fila realmente persistida. Las entidades HTML se comparan con el UTF-8 saneado almacenado por PHP. Estos ajustes preservan el oráculo de datos y no relajan los conflictos.

Límites: transporte HTTP interceptado, no un servidor vivo ni middleware completo; tokens se comprueban en el fixture. La ruta real de cada proyecto debe usar auth/can/CSRF y autorizar su registro antes de delegar. El framework no puede conocer el modelo de artículos. Revisiones de publicación y permisos por registro permanecen en la aplicación; no hay autoguardado de otros campos ni publicación automática. La expiración deja tombstones/versiones y no purga físicamente datos. Evidencia visual local: content-autosave-conflict.png. Pendiente auditoría separada y publicación autorizada.
